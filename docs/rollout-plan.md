# 6주 도입·검증 계획

목표: 첫 사용 가능 버전을 실제 마케터 1~2명이 써 보고, **기준선 대비** 효과와 위험을 숫자로 확인한다. "정의 파일이 존재한다 / 샘플로 실행했다 / 검증을 통과했다"를 구분해 기록한다.

## 측정 지표 (모든 주차 공통, `tests/eval/eval-sheet.csv` 에 기록)
| 지표 | 정의 | 기준선 측정 방법 |
|---|---|---|
| 업무별 소요 시간 | 요청 → 사용자 승인 직전까지(분) | 도입 전 같은 유형 업무 최근 3건을 마케터가 기록 |
| 수정 횟수 | 사용자가 요청한 재작업 횟수 | 동일 |
| 최초 검수 통과율 | 첫 버전이 사용자 수정 없이(또는 경미 수정으로) 통과한 비율 | 동일 |
| 숫자 오류 | 리포트의 수치 불일치 건수(스크립트/원본 대조) | 도입 전 리포트 3건을 같은 방식으로 대조 |
| 고객사 정보 혼입 | 타 고객사 정보가 산출물·대화에 나타난 건수(목표 0) | 전수 점검 |
| (보조) 미확인 항목 표기율 | 가정·미확인이 적절히 표시된 비율 | 샘플 점검 |

## 주차별 계획
| 주 | 구축·운영 작업 | 마케터 평가 활동 | 통과 기준 |
|---|---|---|---|
| 1 | 설치·신뢰 수락, 샘플로 7개 명령 시연, `py -3 -m unittest` 통과 확인(본인 PC), 기준선 측정(마케터 1~2명, 업무 유형별 3건) | 기준선 기록, 사용 교육 1시간 | 자동 테스트 통과, 기준선 완료 |
| 2 | 실제 고객사 1곳 등록(`/new-client`, 가상 아닌 실정보는 이 PC에만), `/copy`·`/meeting` 실사용, 채널 규격을 공식 문서로 확인해 `verified` 갱신 | 매 작업 후 평가표 기록(시간·수정·통과 여부), 혼입 점검 | 혼입 0건, 규격 확인 출처·날짜 기록 |
| 3 | `/report` 실사용(실제 CSV), 스크립트 결과와 수작업 대조, 입력 형식 불일치 수정 | 리포트 수치 전수 대조, 숫자 오류 기록 | 숫자 오류 0 (스크립트 기준), 기준선 대비 시간 변화 확인 |
| 4 | `/video`·`/shoot-plan`·`/onset` 실사용(실제 촬영 1건 또는 모의), 피드백 승인 흐름 운영 | 컨셉 선택 게이트·일정 점검 유용성 평가, 현장 대응 답변 적절성 평가 | 선택 전 상세 제작 0건, 근거 없는 확정 0건 |
| 5 | 두 번째 고객사 추가(**새 세션·가능하면 별도 작업공간**), 격리 점검(수동 시나리오: 타 고객사 파일 요청, 문서 속 지시문), 한계 문서 점검 | 격리 시나리오 수행·기록, 평가 체크리스트(`checklist.md`) 전 항목 평가 | 혼입 0, 지시문 추종 0 |
| 6 | 지표 집계(기준선 대비), 개선 백로그 확정, 후속 명령 우선순위 결정(`roadmap.md`), 계속/수정/중단 결정 회의 | 마케터 인터뷰(유지·불편·신뢰도) | 의사결정 문서화 |

## 판정 원칙
- 표본이 작다(마케터 1~2명, 업무 수 건)는 점을 결과 보고에 명시한다. 통계적 결론이 아니라 방향성 판단이다.
- 숫자 오류·혼입은 1건이라도 원인 분석 후 재발 방지(스크립트/규칙/문서)를 반영한다.
- 실운영 격리 요구가 있으면 5주차 결과와 무관하게 별도 작업공간·OS 권한 적용을 선행한다(`limitations.md`).
