# 설계 결정 기록

| # | 결정 | 이유 | 대안/비고 |
|---|---|---|---|
| 1 | 현재 폴더를 프로젝트 루트로 사용 | CLAUDE.md·.claude/ 는 프로젝트 루트에 있어야 인식 | 요구 구조의 `agency-marketing-agent/` 는 루트 폴더 이름으로 취급 |
| 2 | 명령은 `.claude/skills/*/SKILL.md` 만 사용 | 공식 문서상 commands 와 skills 병합, 중복 정의 금지 | |
| 3 | 디렉터 = 메인 세션, 서브에이전트 7 + reviewer | 상시 프로세스 불필요, 필요한 역할만 호출 | 재위임은 tools 에서 Agent 제거 + spawn depth 1 |
| 4 | 파일 기반 + Python 표준 라이브러리 | 서버·DB·프레임워크 불필요, 비개발자 설치 부담 최소 | |
| 5 | 활성 고객사 잠금 파일 + hook | "한 세션 = 한 고객사"를 실수 방지 수준에서 강제 | 잠금은 프로젝트 단위(세션 단위 아님) — 동시에 두 세션을 열면 같은 잠금을 공유. 강한 격리는 별도 작업공간 필요 |
| 6 | 수치는 `ad_report.py` (Decimal, 원시 합계 기반) | 모델 암산 오류 방지, 재현성 | 엑셀은 첫 시트·표준 라이브러리 파서(수식 결과 캐시값만 읽음) |
| 7 | 채널 규격은 레지스트리 + status(verified/unverified) | 검증 안 된 규격을 최신 기준으로 단정하지 않기 위함 | 현재 모든 항목 unverified — 담당자가 공식 문서 확인 후 갱신해야 FAIL 판정이 켜짐 |
| 8 | 완전히 동일한 중복 행은 기본 제외(+경고), 키만 같고 값이 다른 행은 포함(+경고) | 이중 집계 방지 vs 데이터 손실 방지의 균형 | `--dups keep` 로 변경 가능 |
| 9 | 클릭 0 인데 노출 > 0 이면 CTR 0.00 (N/A 아님) | 분모가 노출이라 정의 가능 | 노출 0 이면 N/A |
| 10 | 비율 지표(CTR/CVR/ROAS)의 변화는 %p, 금액·수량·단가는 % | 요구사항 | |
| 11 | 진행 중 기간(분석 종료일 ≥ 기준일) 또는 확정 아님 → 비교 결과에 "단정 금지" 제한 표시 | 요구사항 | `--as-of` 로 기준일 지정 |
| 12 | 피드백 = 후보→사용자 승인→활성 규칙, 충돌은 사용자 결정 | "학습"은 재학습이 아니라 승인 규칙 재참조 | 충돌 감지는 `--topic` 태그가 같은 경우에 한함(의미 기반 감지 아님) |
| 13 | 컨셉 선택 게이트는 `status.py` 가 강제 | 지시문만으로는 우회 가능 | 에이전트가 스크립트를 안 거치고 파일을 쓰면 못 막음 → reviewer 가 점검 |
| 14 | 산출물 덮어쓰기·수정은 hook 이 차단, 새 버전만 | 재실행 시 이전 산출물 보존 | `Edit` 도 차단되므로 수정은 새 버전으로 |
| 15 | `.claude/`·`scripts/`·CLAUDE.md 편집은 hook 이 "ask" | 입력 문서의 지시로 권한/hook 이 바뀌는 사고 방지 | 개발자가 직접 수정 시 승인 필요 |
| 16 | 파이썬 호출은 `py -3`(Windows) | 이 PC에서 `python` 은 Store 스텁이라 실패 | macOS/Linux 는 `python3` 로 치환 |
