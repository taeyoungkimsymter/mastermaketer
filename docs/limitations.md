# 한계와 알려진 제약

## 가장 중요한 한계: 고객사 격리는 보안 경계가 아니다
CLAUDE.md, 권한 규칙, hook, 활성 고객사 잠금은 모두 **실수 방지 장치**입니다. 같은 폴더·같은 OS 사용자 권한에서 동작하므로 다음은 **막지 못합니다**(자동 테스트 `test_KNOWN_GAPS_*` 가 일부를 고정).

| 경로 | 막는가 | 설명 |
|---|---|---|
| Read/Write/Edit/Glob/Grep 로 다른 고객사 경로 접근 | 막음 (hook) | `..`·상대경로·절대경로는 resolve 후 비교. 심볼릭 링크/정션도 resolve 로 풀어 비교(Windows 에서는 링크 생성 권한이 없어 **자동 테스트 미검증**) |
| `clients/` 루트·프로젝트 루트 전체 검색 | 막음 | Glob/Grep 의 path 가 루트/clients 일 때 |
| Bash 명령 문자열에 `clients/<다른 id>` | 막음(최선 노력) | 정규식 기반 |
| Bash 에서 경로를 쪼개거나 `cd clients; cat other/…` | **못 막음** | 문자열 패턴을 피하는 명령 |
| 스크립트·`python -c` 내부에서 만든 경로 | **못 막음** | hook 은 명령 문자열만 본다 |
| MCP 도구(Notion, Slack, 파일 서버 등) | **못 막음** | matcher 에 MCP 를 넣지 않았고, 외부 서비스 접근은 별개 문제 |
| 서브에이전트에서의 hook 적용 | 로컬 스모크 테스트에서 메인 세션만 확인 | 서브에이전트 도구 호출에 동일하게 적용되는지 **미검증** |
| 두 개의 Claude 세션을 같은 폴더에서 동시에 사용 | **못 막음** | 활성 고객사 잠금 파일을 공유 |
| 사람이 직접 파일을 복사/이동 | 해당 없음 | |
| 입력 문서의 지시문을 모델이 따르는지 | 확정 불가 | 탐지 스크립트는 최선 노력, 모델 행동은 평가 체크리스트로만 점검 |

**고객사 간 접근을 확실히 차단해야 하는 실운영 환경에서는** 고객사별 **별도 작업공간(별도 폴더 + 별도 OS 계정 또는 컨테이너/VM)**, OS 파일 권한, 별도 MCP/API 자격증명이 필요합니다. 별도 폴더만으로는 강한 격리가 아닙니다.

## 권한 설정
- 워크스페이스 신뢰(trust) 수락 전에는 `settings.json` 의 `permissions.allow` 가 무시됩니다(스모크 테스트에서 확인). hook 은 동작했습니다.
- `deny` 의 `mcp__claude_ai_Slack__*` 3개는 이 환경에 연결된 도구 이름 기준입니다. 다른 MCP 서버(Gmail, Notion, 캘린더 등)를 연결하면 **쓰기·발송 도구를 별도로 deny 해야** 합니다. MCP 를 연결해도 Slack 명령·모바일 화면·예약 실행·외부 알림이 자동으로 생기지 않습니다(각각 추가 구성과 인증 필요).
- 실패 시 차단(`onFailure: block`)은 2.1.295 이상 기능이라 쓰지 않았고, 대신 hook 스크립트가 예외 시 exit 2 로 닫히게(fail-closed) 만들었습니다. `python`/`py` 자체를 실행하지 못하면 hook 이 비차단 오류로 끝나 **차단되지 않을 수 있습니다**.

## 기능 제약
- 채널 규격(`channel-specs.json`)은 **전부 미검증(unverified)** 입니다. 글자 수 초과는 참고 표시만 하고 FAIL 판정하지 않습니다. 담당자가 공식 문서로 확인해 `status: verified`, `source`, `checked_at` 을 채워야 판정이 켜집니다.
- 광고 표현 검수는 키워드 기반 보조 도구이며 법적 승인·심의 통과가 아닙니다.
- `ad_report.py`: CSV(UTF-8/CP949)와 XLSX 첫 시트만. XLSX 는 저장된 값만 읽고 수식을 계산하지 않습니다. 다중 시트·병합 셀·피벗은 미지원. 광고 API 연동 없음.
- 리서치: 웹 검색 도구가 없으면 제공 자료 기준으로만 작성(최신 정보를 만들지 않음).
- 영상 입력은 직접 분석하지 않습니다(자막·타임코드·대표 프레임 요청). 이미지 콘티 생성·예약·알림·PPT/PDF 출력은 없습니다.
- 서브에이전트 간 병렬/파일 충돌 방지는 지시문 수준입니다(도구로 강제하지 않음). 상태 파일 갱신 책임자 규칙도 지시문 + 스크립트 관례입니다.
- `/weekly` 등 후속 명령은 **등록하지 않았습니다**(빈 명령 방지).
- 가상 데이터 테스트는 실운영 보안이나 창작 품질을 입증하지 않습니다.
